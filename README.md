# Prestige Route Optimizer

Physics-based idle game's Prestige route optimizer built from observed play data.

The deployed site currently runs the established v5 planner as the primary recommendation and the rebuilt causal v6 model in visible shadow mode. v6 predictions are logged beside v5 decisions and will become primary only after walk-forward replay and live search-stability evidence are strong enough. See [`docs/model-v6.md`](docs/model-v6.md).

## Features

- Rapidly update Level, cash, DPS, and each upgrade's current value / next cost / increment.
- Recommend the highest estimated marginal benefit per dollar from currently affordable upgrades.
- The current-best recommendation includes its own one-click purchase mirror, so the user can buy it in-game and sync the optimizer without locating the matching upgrade tile.
- One-click purchase mirroring deducts the purchase from tracked cash and updates projected DPS, current value, next increment, and next cost.
- Reducer's first observed/derived price is $75K: with ×1.58 price growth this reproduces the observed 10-buy total of about $12.41M.
- The DPS calibration input accepts the game's suffix notation directly (`2.33K`, `1.2M`, etc.) and persists the resulting calibration for subsequent projections.
- Displayed DPS is derived from the complete current upgrade state instead of accumulated purchase history; entering an observed DPS calibrates the model without making later state edits stale.
- Spike Count starts at an observed `$1.2K` next cost, and Feed Rate at `$400` with the observed `×1.4` cost progression.
- One-click full-budget mirroring applies the currently displayed investment plan in one action, including repeated purchases and cumulative price/increment growth.
- Level Up mirrors its immediate cash reward. Observed Lv3–9 rewards are stored directly; Lv10+ follows the observed `346.35 × 1.36^(level-10)` progression with cent truncation.
- Level Up also starts the next level's wall-clock timer automatically. Exact EXP-full records and missed-record press-to-press fallbacks are kept distinct, while persistent level-start anchors allow elapsed time to be recovered from any recorded level.
- The fast-play EXP-full button now performs the optimizer-side Level Up in the same action: it records the exact elapsed time, applies the observed Level Up cash reward, advances the level, and immediately starts the next timer.
- That primary EXP-full/Level-Up control is anchored beside the Level and live timer in the game-mirror panel, so recommendation text changing height cannot move the button. Timer restart, history, and recovery-only Level Up controls are kept in a separate low-priority section below the main panel.
- Recommendation text explicitly separates the best currently affordable purchase from the budget-agnostic ROI leader and the next price threshold, avoiding misleading "leader" wording while cash is still accumulating.
- Timestamped run/action logs capture purchases, bundle syncs, level transitions, cash/DPS calibration, recommendation context, and upgrade snapshots. Logs can be copied as JSON or saved as CSV; a Lv50→Lv1 reset is automatically marked as a new Prestige run.
- The `Prestige → 新周回開始` action performs the actual optimizer-side Prestige reset: Level, cash, normal upgrades, current timing/history, and live DPS calibration reset, while permanent upgrades, model settings, cash-tracking preference, and the cross-run action log are preserved. The separate `全状態を初期化` action is explicitly destructive and is not for normal Prestige use.
- Displayed DPS is treated as deterministic model output multiplied by a live calibration factor, so population/instance-dependent in-game modifiers can be absorbed without re-fitting the underlying upgrade formula.
- Live-cash tracking advances the balance from a learned or manually overridden $/s estimate so the user does not need to retype a constantly changing balance.
- Cash tracking defaults to AUTO and learns from both real Cash-sync deltas and historical manual $/s observations. Manual-rate history is preferred when enough same-level samples exist, obvious scale outliers are rejected in log space, and older samples are scaled toward the current upgrade/permanent-power state. Manual $/s remains available as an override.
- Causal v6 shadow modeling learns per-level EXP *work* by integrating state-dependent progression over the actual purchase timeline instead of treating historical elapsed seconds as the state variable. Purchases change the rate only after their timestamps; current ETA comes from remaining inferred work divided by the current causal rate.
- v6 keeps observed telemetry separate from predictions. State paste can now capture `Feed rate`, `Feed rate (small)`, `Crush rate`, ore HP, and Normal/Rare/Epic/Orichalcum values. Direct crush/feed telemetry changes the inferred bottleneck response without changing the canonical work-unit scale when the observation first arrives.
- v6 runs an event-driven purchase simulator: cash and EXP advance together until affordability or EXP-full events, purchase/reflect latency does not pause the game, and waits are not allowed to cross the current level boundary. Every shadow decision is solved with two search budgets and reports whether the first action is search-stable.
- v6 exposes separate Active and AFK policies. Active mode optimizes progression; AFK mode assumes no later user interaction and searches only purchases that can be made before leaving for the configured return horizon.
- The v6 campaign layer reports pure-Ingot continue-vs-reset economics after Lv50, but deliberately marks the full campaign decision as underdetermined while the required Prestige-count gate is incomplete and the automatic Prestige multiplier progression law is still unobserved. It does not invent a scalar exchange rate between one Prestige count and one Ingot.
- JSON/CSV decision logs now include `observed`, `predicted`, and `modelVersion` fields plus the compact v6 shadow result. `node tools/replay-v6.mjs <export.json>` performs no-future-information walk-forward validation of level-work priors.
- The primary recommendation is time-aware rather than affordable-only ROI: a same-level beam search considers up to eight purchases, estimates wait-to-afford from empirical cash pace, and refuses to plan a wait beyond the predicted EXP-full boundary because the next Level Up changes both cash and the decision state. The remaining-to-Lv50 benefit still values early purchases over the whole run, while the current-level horizon prevents long Power/Reducer waits from starving immediately useful cheap upgrades.
- Level progression is no longer capped at 50. The observed post-50 rule is now authoritative in the optimizer: `Ingots gained = Level - 49`, so every extra level is one marginal Ingot. At Lv50+ the same-level planner therefore optimizes time-to-next-Ingot directly while still refusing to invent unobserved post-50 Level Up cash rewards.
- Rare Ore Rate is not capped at 10%. The observed 10.0% state still offers a `$52.43B +0.5` purchase, so the optimizer leaves the upper cap open until an actual in-game maximum is observed.
- Post-50 EXP forecasts use recent completed Lv51+ timings from the current run instead of falling back to a 60-second generic guess. The Prestige-efficiency panel compares the rolling next-Ingot forecast against the exact current-run Lv2→50 seconds per Ingot; manual probes remain available as a verification channel and are checked against the known linear rule.
- High-frequency observational log entries no longer store redundant recommendation snapshots, and the retained action-log window is expanded for the long 25-Prestige/250-Ingot campaign without multiplying the old per-entry payload.
- EXP-full timing is an ensemble forecast rather than a single latest-run extrapolation. It combines the same level across prior runs with the current run's recent pace, shows an early-to-late range, and uses a deliberately earlier safety bound for purchase-wait gating so a slow previous route cannot make the optimizer wait past a plausible gauge completion.
- Exact EXP-full action-log entries also persist the ETA range that was still predicted when the gauge actually filled, making future exports directly usable for forecast-calibration analysis.
- Legacy v5 route-progress effects are separated from raw cash/DPS effects: the empirical timing model gives sublinear credit to DPS-like upgrades, full expected-value credit to Rare, smaller supply credit to Feed, and no direct EXP credit to Spike Size. These coefficients remain only in the primary v5 fallback while causal v6 is shadow-validated; they are not the v6 physics model.
- Purchase-reflect actions treat the game as authoritative. If real in-game Cash has already made a purchase possible while the stochastic Cash estimate is stale, the optimizer can still mirror the purchase; its tracked balance falls to a conservative zero lower bound instead of blocking the control.
- Real purchase/reflect latency is learned from action logs but treated as decision cadence rather than dead time, because the idle game keeps progressing while the user clicks and mirrors purchases. The latency is used as a near-EXP-full deadline buffer instead of suppressing an otherwise useful upgrade merely because its single-level modeled saving is smaller than the click/reflect interval.
- Legacy v5 values persistent Lv50+ upgrades over a rolling multi-Ingot horizon. Causal v6 instead forecasts level-work forward until the pure-Ingot marginal time reaches the measured reset-cycle time (with a bounded computational lookahead); the Prestige-count constraint is reported separately until its multiplier law is identified.
- Duplicate paste/change Cash syncs within one second are coalesced so the run log contains one observation instead of two near-identical events.
- New action-log entries also snapshot permanent progression, and unusually large DPS live-calibration factors warn that a permanent-upgrade setting may be stale rather than silently treating the whole discrepancy as an instance-population effect.
- Cash accepts the game's compact notation directly (`47.65M`, `850K`, `1.2B`) so no manual unit conversion is needed.
- Power uses the observed growing increment sequence (+2.2 initially, then +0.4 to the increment per purchase).
- Displayed DPS is now derived from the controlled observations rather than point-by-point curve tuning: `0.73245 × PrestigeDMG × CrushPower × (Speed/10) × (Power/2) × Reducer^2.25 × (SpikeCount/4) × (Gravity/9.81)^0.715 × calibration`. `Speed` is the already-reduced in-game RPM, so the Reducer term is `R^(1 + 1.25)`: one power restores the hidden nominal-speed division and the remaining `R^1.25` is the measured torque/DPS gain. Gravity uses a power law fitted to the controlled 15.31→17.31 test and cross-checked against the current run. Spike Size is deliberately excluded from displayed DPS because observations only establish reach/physical-throughput effects, not a displayed-DPS contribution.
- Upgrading from the old DPS model resets the obsolete carried calibration factor to `1`, preventing a past calibration point from biasing later high-Reducer predictions. Manual DPS entry can still apply a fresh residual calibration when desired.
- The primary panel mirrors the game's visual hierarchy: compact cash/DPS/level strip followed by the exact 4×2 upgrade order `Speed / Power / Reducer / Rare` then `Gravity / Spike Count / Spike Size / Feed`, with current values dominant and optimizer-only rank/effect information secondary.
- Upgrade actions use a responsive card layout, keeping the purchase button visible without horizontal scrolling.
- Full-budget proposals show each upgrade's current value → proposed value, with total spend kept secondary, and can be mirrored with one click.
- Parse the same Japanese state templates used during manual testing.
- Built-in level timer, persistent level-start anchors, and run history.
- Persist all state locally in the browser.
- Editable empirical model parameters for Reducer, Gravity, Feed Rate, and Spike Size.

The optimizer deliberately keeps uncertain mechanics editable instead of pretending they are exact. The primary workflow is to mirror one real purchase at a time and let the recommendation recalculate immediately.
